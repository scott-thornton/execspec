# Verdict semantics - Version: Verdict Semantics 1

Every verdict execspec produces has a precise meaning. This document
defines what each verdict establishes and what it does not, with the
same normative rigor as `docs/semantic-model.md`.

## Conformance (execspec test)

### PASS

**Establishes:** For the scenario's exact steps, in a fresh host
process, against a digest-matched implementation, every operation
produced an output that is semantically equal to the expected value
under the canonical equality rules (`docs/semantic-model.md` §4).

**Does not establish:** That the implementation is correct for inputs
or sequences not covered by the scenario. That the implementation
satisfies any intent beyond the literal observations compared.

**Exit code:** 0 only when every scenario in the specification passes.

### FAIL

**Establishes:** At least one step in the scenario produced an output
that is not semantically equal to the expected value. The exact step
number, the structural diff path, and both values are reported.

**Failure classes:**

| Class | Meaning |
| ----- | ------- |
| `ExpectationFailure` | An expectEqual step found differences; structural paths and both values are reported. |
| `HandshakeFailure` | The host did not complete the protocol handshake (digest mismatch, version mismatch, or process exit before helloAck). No operations were dispatched. |
| `HostCrashFailure` | The host process exited before responding to a request. |
| `OperationTimeoutFailure` | The host did not respond within the timeout. |
| `InvalidOutputFailure` | The host returned a value that does not decode or validate against the declared output type. |
| `ProtocolFailure` | The host violated the protocol (malformed message, wrong request ID, reported an invalid request). |
| `HostShutdownFailure` | The host did not exit cleanly after stdin was closed. |

## Compatibility (execspec compatible)

### compatible: yes

**Establishes:** The structural analysis found no breaking changes:
- Every operation in the old spec exists in the new spec.
- Operation input/output types pass variance rules (input
  contravariance, output covariance).
- Every type declaration in the old spec exists in the new spec with
  no breaking field or case changes.
- Every scenario in the old spec exists in the new spec with
  identical step contents (operations, bindings, expressions, and
  expected values).

**Does not establish:**
- That implementations of the new spec will satisfy the old
  behavioral contract (this is a structural analysis; run conformance
  against both specs for behavioral evidence).
- That the semantic model has not changed (governed by the digest
  lineage in `docs/compatibility.md`).
- That the new spec's scenarios are a superset of the old spec's
  behavioral guarantees (only that identical old scenarios are
  preserved).

**Exit code:** 0.

### compatible: no

**Establishes:** At least one breaking change was found. Every
breaking change is listed with its scope and description.

**Exit code:** 1.

## Differential probe (execspec probe)

### N disagreements

**Establishes:** For N of the generated inputs, at least two hosts
produced semantically different outputs. The exact input and both
output values are reported for each disagreement.

**Does not establish:** The full extent of disagreement between
implementations (only the specific inputs that were tested).

**Exit code:** 1.

### N failed (fail-closed)

**Establishes:** N probes could not complete comparison. Each failure
is classified:

| Category | Meaning |
| -------- | ------- |
| `crash` | The host process exited before responding. |
| `decode` | The host's output failed to decode or validate against the declared type. |
| `timeout` | The host did not respond within the timeout. |
| `other` | Any other failure (host unavailable, protocol error). |

**Does not establish:** Anything about agreement or disagreement.
Inability to verify is not evidence of agreement.

**Exit code:** 1.

### 0 disagreements, 0 failed

**Establishes:** For the specific inputs generated by
`(digest, operationId, iteration, seed)`, all hosts produced identical
outputs.

**Does not establish:**
- That the implementations agree on all possible inputs (only the
  tested subset).
- That the generated inputs covered the relevant edge cases.
- That the generator's type-directed distribution is representative
  of real-world usage.

**Exit code:** 0.

## Digest (specificationDigest)

**Establishes:** The SHA-256 hash of the canonical semantic IR bytes,
domain-separated by the semantic-model lineage prefix. Two
specifications with the same digest have the same canonical semantic
content.

**Does not establish:** That two specifications with different digests
are incompatible (they may differ only in declaration order, scenario
step order, or metadata).
